### 3.1 顺序校验的方法说明

第 15 项**没有**用被测代码自己的绘图逻辑来验证自己，而是独立完成：

1. 浏览器内导出图板 PNG（拦截 `toBlob`，阻止真实下载）；
2. 浏览器外用 PIL 打开该 PNG，按 `assets/app.js` 中记录的画板几何裁出三个面板区域，
   各自缩到 16×16 灰度签名；
3. 同样把三张**源图**按 canvas 的 contain-fit 逻辑放进 412×740 白底画布，缩到 16×16；
4. 逐一计算平均绝对误差，取最小者为匹配项。

实测误差矩阵（行＝图板面板，列＝候选源图face-002 / pose-003 / outfit-004）：

```
[[ 4.36, 70.35, 60.48],
 [67.36,  0.54, 75.20],
 [64.29, 76.47,  0.92]]
```

对角线分别为 4.36 / 0.54 / 0.92，非对角线均在 60 以上，区分度充分，
**顺序判定为 脸 → 姿势 → 服装，正确**。

## 6. 环境注意事项（供后续接手者）

1. 本机设置了 `HTTP_PROXY`，Chrome 访问 localhost 必须加 `--no-proxy-server`，
   否则会拿到 `chrome-error://chromewebdata/`。已内置在 `scripts/browser_test.mjs`。
2. 本机 Chrome 自带 sandbox 无法初始化、GPU 进程会崩溃，需加 `--no-sandbox`
   `--disable-gpu --disable-software-rasterizer`。同样已内置。
3. Chrome profile 复用 `work/chrome-profile/`（`work/` 已被 `.gitignore` 忽略），
   测试结束**不删除**目录，避免触发文件删除权限请求。
4. 本地 HTTP 服务需以**后台常驻任务**运行；若用 `nohup … &` 随 shell 退出，
   进程会被回收，浏览器测试会因连不上服务而失败。
5. `scripts/check_order.py` 需要带 Pillow 的 Python；`scripts/browser_test.mjs`
   会在运行时自动探测（`python3` → PATH → `$HOME/anaconda3/bin/python3` 等），
   探测不到时该子项会明确标记为失败而非静默跳过。
